# 2026-09-19

## 修复：青番AI番茄钟 hvigor 构建 SignHap 失败（签名材料重建）

目标：让 `hvigor assembleHap` 通过 SignHap，产出可安装的已签名 HAP。

### 根因
- `build-profile.json5` 的 signingConfigs "default" 原来指向已删除的 `.ohos\config\*` 签名材料，且 storePassword/keyPassword 是明文 `123456`。
- hvigor 的 SignHap 在 `decryptPwd` 中强制要求 storePassword/keyPassword 字段长度 ≥32 且为偶数（否则报 `00303116 Configuration Error`），并且真值是用 DevEco 私有密文方案解密的，明文 `123456` 直接被拒。

### 解决方案（已全部跑通）
1. 用 SDK 预置测试密钥库重建调试签名材料（`c:/Program Files/Huawei/DevEco Studio/sdk/default/openharmony/toolchains/lib/` 下的 `OpenHarmony.p12` + `hap-sign-tool.jar`）。脚本 `.sign/gen9.js`：
   - 复制 `OpenHarmony.p12` → `.sign/sign.p12`
   - `generate-app-cert`（keyAlias `openharmony application release`，issuer 必须用 **C 在前** 的 DN `C=CN, O=OpenHarmony, OU=OpenHarmony Team, CN=OpenHarmony Application CA`，issuerKeyAlias `openharmony application ca`，outForm certChain）→ `.sign/appCertChain.cer`
   - `sign-profile` 用 `OpenHarmonyProfileRelease.pem`（需 reverse 成 leaf→appCA→root 顺序）→ `.sign/debug.p7b`
   - profile JSON 的 `development-certificate` 必须是 **URL-safe base64**（无 PEM 头，+/→-, /→_, 去 =）
2. 复刻 DevEco `DecipherUtil` 的密码密文方案，生成 `.sign/material/{fd,ac,ce}` 密钥文件树 + 加密后密码。脚本 `.sign/gen11.js`（已验证可解密回 `123456`）。关键：
   - rootKey = pbkdf2Sync( (fd0^fd1^fd2^component).toString('utf8'), salt, 10000, 16, 'sha256' )，component = `[49,243,9,115,214,175,91,184,211,190,177,88,101,131,192,119]`
   - 两个密码 blob 格式：`[4字节大端长度L][12字节IV][密文][16字节GCM tag]`，aes-128-gcm
   - materialDir = `path.resolve(storeFile,"..")` = `.sign`（storeFile 是 `.sign/sign.p12`），所以 material 在 `.sign/material`
3. `build-profile.json5` 的 keyPassword/storePassword 改为 gen11 产出的加密串（76 字符，`00000016...`），certpath/profile/storeFile 指向 `.sign/*`。

### 验证结果
- `c:/Program Files/Huawei/DevEco Studio/tools/hvigor/bin/hvigorw.bat assembleHap`（设置 DEVECO_SDK_HOME/HOS_SDK_HOME/OHOS_SDK_HOME 指向 SDK）→ **BUILD SUCCESSFUL**（约 40s）。
- 产出已签名 HAP：`entry/build/default/outputs/default/entry-default-signed.hap`（1,236,396 字节，zip 魔数 PK）。
- `hap-sign-tool.jar verify-app` 对该 HAP → `verify-app success`，证书链 Root CA → App CA → App Release，profile type debug，Digest verify true。

### 备注
- `ls/head/cat/find/grep/tail/dirname/cd` 等 shell 命令在本机被 shim 破坏，需用绝对路径 `node.exe` 或 `java.exe` 配合文件重定向。
- git bash 包装脚本会报 `dirname: command not found` / `cd: null directory` 噪声，可忽略。
- 辅助脚本：`.sign/gen9.js`（签名材料）、`.sign/gen11.js`（加密密码+material）、`.sign/verify.js`（验证加密密码可解密为 123456）、`.sign/verify_build.log`（verify-app 输出）。
