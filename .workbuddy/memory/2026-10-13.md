## 三端统一：升级经验公式 + 徽章口径（2026-10-13 下午）

### 统一后的唯一口径（三端必须一致，改动前先看这里）

- **升级所需经验**：`expForLevel(level) = 200 + (level - 1) * 100`。
  语义是「参数 = 当前等级，返回 = 当前等级 → 下一级所需经验」：L1→L2 需 200、L7→L8 需 800、L10→L11 需 1100。
  鸿蒙 `Types.ets:expForLevel` / 小程序 `utils/state.js:expForLevel` / Web `store.js:nextLevelExp` 三处同式。
- **旧档归一** `normalizeLevel()`：等级保留，`exp` 按进度百分比折算（`exp / oldNext * newNext`，只在 `exp <= oldNext` 时折算），再 while 进位；幂等，可反复调用。
- **徽章四类进度**（阈值见各自 `BADGE_TIER_GOALS`）：
  | id | 进度口径 | 青铜/白银/黄金/钻石 |

  | b1 | 连续签到天数 | 7 / 14 / 30 / 60 |
  | b2 | 累计番茄**个数** | 10 / 50 / 200 / 500 |
  | b3 | 累计专注**分钟** | 6000 / 12000 / 30000 / 60000 |
  | b4 | 月度冠军**次数** | 1 / 2 / 3 / 5 |
  阶段名三端统一为 `未解锁 / 青铜 / 白银 / 黄金 / 钻石`（小程序端旧的「铜徽章/银徽章/金徽章/钻石徽章」已废弃）；**解锁条件统一为「达到第一档」**。四枚徽章命名统一为 `连续 7 天 / 番茄丰收 / 专注达人 / 月度冠军`。

## 鸿蒙端桌面卡片空白 Bug 修复（下午）

**用户反馈**：鸿蒙端添加桌面卡片后，卡片不显示内容、只有空白。

### 根因（两个独立 bug）

1. **【致命，导致空白】`WidgetCard.ets` 在 `@Component struct` 里用了 `private get theme()`。**
   ArkTS 编译器会**静默丢弃** struct 里的 `get`/`set` 访问器 —— 生成类里根本没有 `theme` 成员，
   但 `initialRender()` 首句就是 `Column.backgroundColor(this.theme.cardBg)` →
   运行时 `this.theme` 为 `undefined` → 抛 `TypeError` → `initialRender()` 中断 → **整块空白**。
   全程 **BUILD SUCCESSFUL、零报错零告警**，所以一直没被发现。
   证据：`entry/build/default/cache/.../debug_widget/.../WidgetCard.ts` 的类成员只有
   `initialRender / compactLayout / wideLayout / metricCell / largeLayout / rerender / ...`，无 `theme`。
   官方口径：「ArkTS 自定义组件 struct 中不支持成员变量的 get/set 方法，编译构建后不会生成对应逻辑，运行会报错」。
   修复：改为普通字段 `private theme: ThemeDef = themeOf('green');`（重建后生成产物第 24 行出现 `this.theme = themeOf('green');`）。

2. **【尺寸全错】`QfWidgetAbility.dimensionOf()` 在等字符串 `'2*2'`，系统下发的是数字。**
   SDK 注释写的就是 `DIMENSION_KEY: FormDimension.Dimension_1_2`，
   枚举为 `Dimension_1_2=1 / 2_2=2 / 2_4=3 / 4_4=4`；
   `WidgetPicker.addToDesktop()` 走 `openFormManager` 传的也是数字（2/3/4）。
   → 数字永远匹配不上字符串分支 → **永远回退 `'2*2'`**，2×4 / 4×4 卡片全按 2×2 小布局渲染。
   修复：`dimensionOf` 增加 `typeof d === 'number'` 分支 + `dimNameOf(code)` 映射，保留字符串容错。

3. **【附带修复】载荷按尺寸少发 key。** 原来只有 4×4 才下发 `min/streak/trees/progressPct`，
   其他尺寸下卡片页这些 `@LocalStorageProp` 只能退回默认值 `'0'`（假数据）。改为**全量下发** 8 个 key + `title`。

4. **【健壮性】`onUpdateForm` 的尺寸缓存会随进程回收丢失。**
   系统定时刷新（`updateDuration: 1`，每 30 分钟）不携带尺寸，且此时 Ability 可能已重建、内存 `dimMap` 为空，
   一张 4×4 卡片半小时后会悄悄变回 2×2。改为「内存 Map → Preferences（`this.context`，文件名 `qf_widget_dims`）→ 2*2」逐级回退，
   `onAddForm` 落盘、`onRemoveForm` 清理。
